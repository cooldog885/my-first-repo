## 阶段 1：技术就绪（代码 / 构建）
- [x] 🔧 签名配置已从硬编码移入 `gradle.properties`（见下方“安全改进”）
- [x] 🔧 `AndroidManifest` 设 `android:allowBackup="false"`（避免本地财务数据被云备份泄露）
- [x] ✅ 权限最小化：仅 `WRITE_EXTERNAL_STORAGE`（上限 API 28），无 INTERNET 权限
- [ ] 🔧 **（关键阻塞项）将 targetSdk / compileSdk 升到 36**
      - 原因：Google Play 自 2026-08 起新应用必须 `targetSdk ≥ 36`（Android 16）。
      - 当前 AGP 8.2.2 最高支持 compileSdk 34，需连带升级：
        - `build.gradle.kts`：`id("com.android.application") version "8.7.3"`（或更新）
        - `gradle/wrapper/gradle-wrapper.properties`：`distributionUrl` → Gradle 8.9+
        - `app/build.gradle.kts`：`compileSdk = 36`、`targetSdk = 36`
      - ⚠️ 此改动会触发 AGP/Gradle 联网下载，可能带来兼容性回归，**建议单独提交并充分自测后再上架**。
- [ ] 🔧 **（建议）修改 applicationId 为你自有域名反写**
      - `app/build.gradle.kts`：`applicationId = "com.example.foldledger"` → 例如 `"com.yourname.foldledger"`
      - 注意：改包名后旧版用户无法覆盖安装，需作为全新应用发布。
- [ ] 🔧 如启用混淆：`app/build.gradle.kts` 将 `isMinifyEnabled = true`（当前为 false，便于排错）

## 阶段 3：Google Play 上架流程
1. 🖥️ 注册 Google Play 开发者（一次性 $25），登录 Play Console。
2. 🖥️ 创建应用 → 填写商品详情（名称/简介/截图/图标/特色图/分类/联系方式）。
3. 🖥️ 填写 **Data safety（数据安全）表单**：声明不收集、不共享数据（见 STORE-LISTING 要点）。
4. 🖥️ 设置内容分级（问卷 → Everyone）。
5. 🖥️ 上传 `app-release.aab`（**用 AAB，不要 APK**）。
6. 🖥️ 填写隐私政策 URL。
7. 🖥️ 选择发布国家/地区，提交审核（通常数小时至数天）。
8. 🖥️ 审核通过后在 Production 轨道发布。

## 阶段 4：国内主流安卓商店流程（概述）
| 商店 | 开发者账号 | 备注 |
|---|---|---|
| 应用宝（腾讯） | 企鹅号/应用宝开发者，需资质 | 个人可发工具类 |
| 华为应用市场 | 华为开发者联盟，个人/企业 | 需实名，部分类目需软著 |
| 小米应用商店 | 小米开放平台 | 个人可发 |
| OPPO / vivo 软件商店 | 各自开放平台 | OPPO/vivo 对金融类较严，纯本地记账一般可按“工具”类 |
| 百度手机助手 / 360 手机助手 | 各自平台 | 个人可发，审核较松 |

通用步骤：注册→实名/资质→创建应用→上传 APK（国内多用 APK 或平台托管 AAB）→填资料/截图/隐私→提交审核→上架。
> 提示：记账/财务类在部分商店可能被要求提供《计算机软件著作权》或《 ICP 备案》/《增值电信业务许可证》。纯本地、无交易功能通常可按“实用工具”申报，降低门槛；如被要求资质，再补软著（约 1–2 个月）。

---

## 阶段 5：发版与更新
- 每次更新：递增 `versionCode`（`app/build.gradle.kts`），`versionName` 按需。
- 重新 `bundleRelease` / `assembleRelease`，用**同一 keystore** 签名。
- 在商店后台上传新包并提交审核。
